# yazi audit and plan — 2026-08-18

Installed: **yazi 26.8.15** (1f3588d, 2026-08-15), `ya` the same. Our config was
written 2026-08-07 against what was then current, and carries habits from the
dotfiles-linux config before that. Between those two dates yazi shipped
`v25.12.29`, `v26.1.4`, `v26.1.22`, `v26.5.6` and `v26.8.15` — five releases that
renamed a generation of config keys, removed the old opener parameter syntax, and
added a trash bin, a command palette, a virtual filesystem and native drag-and-drop.

Sources read for this: the upstream `CHANGELOG.md`, the docs site's
`version-26.8.15` snapshot (which matches our binary exactly), the shipped
presets `yazi-default.toml` / `keymap-default.toml` / `theme-dark.toml`, and the
26.8.15 source where the docs were ambiguous.

---

## 1. What is broken right now

### 1.1 Every opener passes no file  ← the big one

`$@`, `$1` and `$0` no longer exist. They were deprecated in v25.12.29 (#3232) in
favour of `%`-style *shell formatting*, and by 26.8.15 the `$` path is gone from
the code entirely: `yazi-fs/src/splatter.rs` only ever looks for `%`, and
`yazi-scheduler/src/process/shell.rs` runs the result as

```rust
Command::new("sh").arg("-c").arg(opt.cmd)   // ← no positional args after it
```

so `$@` in an opener expands to the empty string, not to the selection.

Measured, not assumed — yazi driven in a pty with a probe opener:

```
OLD:[] ONE:[] NEW:[/…/ytest/files/sample.txt]
       ↑ $@     ↑ $1        ↑ %s
```

Everything in our config that takes a file is therefore firing blank:

| Where | Current | Effect today |
| --- | --- | --- |
| `opener.play` | `mpv … "$@"` | mpv opens idle, no file |
| `opener.edit` | `$EDITOR "$@"` | editor opens with no buffer |
| `opener.open` | `xdg-open "$@"` | xdg-open prints usage |
| `opener.browser`, `opener.evince` | `… "$@"` | app opens empty |
| `opener.extract` | `ouch decompress "$@"` | nothing to extract |
| `opener.reveal` | `mediainfo "$1" \| less` | empty pager |
| `opener.add-sub` | `sub-add "'$0'"` | `$0` was *removed* in v25.12.29 |
| keymap `y` | `yazi-yank-clipboard "$@"` | selection never reaches the clipboard |
| keymap `e` | `ouch decompress \"$@\"` | no-op |
| keymap transcode | `transcode \"$1\"` | no-op |

The replacements, per `keymap.md` and `yazi.md`: `%s` all selected paths, `%sN`
the N-th, `%h` the hovered path, `%d` dirnames, `%y` yanked paths, `%S/%H/%D/%Y`
the URL forms, `%%` a literal percent. Note `%h` (hovered) is new and is what
several of our bindings actually want — `transcode` and `add-sub` are
hovered-file operations, not selection operations.

### 1.2 The generated theme is half-ignored

`templates/yazi-theme.toml.tpl` still writes the pre-v25.12.29 key names. yazi
ignores unknown fields silently, so these render and do nothing:

| Ours (dead) | Now |
| --- | --- |
| `[completion]` (whole section) | `[cmp]` |
| `mgr.hovered`, `mgr.preview_hovered` | `indicator.current`, `indicator.preview` |
| `mgr.tab_active`, `mgr.tab_inactive`, `mgr.tab_width` | `[tabs] active` / `inactive` (+ `sep_inner`, `sep_outer`) |
| `status.mode_normal/select/unset` | `[mode] normal_main/_alt`, `select_*`, `unset_*` |
| `status.permissions_t/r/w/x/s` | `status.perm_type/read/write/exec/sep` |
| `status.separator_open/close/style` | `status.sep_left` / `sep_right` as `{ open, close }` |
| `confirm.content` | `confirm.body` |
| `help.on`, `help.run`, `help.desc`, `help.footer` | `help.chord`, `help.action` (footer removed) |

And these sections exist upstream but we never emit them at all: `[app] overall`
(terminal background via OSC 11), `[spot]`, `[indicator] padding`,
`mgr.marker_symbol`, `mgr.symlink_target`, `mgr.syntect_theme` (the code-preview
tmTheme — which is why the file preview's syntax colours have never matched the
rest of the theme), and `th.git` (the git plugin reads its own styles from there
since v26.5.6; ours falls back to its hardcoded magenta/yellow/green).

`theme-apply` also has no yazi poke, so even a correct theme only lands on the
next yazi start. v26.5.6 added the `app:theme` action for exactly this — it
hot-reloads themes and flavors in a running instance, and a `theme` DDS event
lets plugins watch it.

Getting the poke there needs care, and this was measured rather than guessed.
`ya emit` only works from inside a yazi subshell (it needs `$YAZI_ID`), which
`theme-apply` is not. `ya emit-to <id>` does work from outside — driving a live
yazi from a separate process with `ya emit-to 7201 cd /tmp` moved it. But the
receiver `0` broadcast that `ps.pub_to` documents does **not** apply to actions:
`ya emit-to 0 cd /etc` exits 0 and does nothing. Pinning a `--client-id` per
window would work but wants a launcher wrapper and a registry, since two windows
must not share an id.

The route actually taken avoids all of that: broadcast a *message* (which does
support receiver `0`) and let yazi turn it into the action. `theme-apply` runs
`ya pub-to 0 qshell-theme --str ''`; `init.lua` holds
`ps.sub_remote("qshell-theme", function() ya.emit("app:theme", {}) end)`.
Verified end to end — a running instance repainted from red to green when the
theme file changed underneath it, with no restart and no client id.

### 1.3 `[open] rules` overrides the preset, losing new built-ins

We use `rules = [...]`, which replaces the *entire* default rule set rather than
`prepend_rules`. The preset gained rules we silently dropped:

```toml
{ mime = "vfs/{absent,stale}", use = "download" }   # remote file download
{ mime = "trash/**",           use = [ "open", "trash" ] }   # restore / empty
{ url  = "*/",                 use = [ "edit", "open", "reveal" ] }
{ mime = "inode/empty",        use = [ "edit", "reveal" ] }
```

Verified in a pty that `g` ⇒ `t` does open the trash bin (`trash:///@//` loads),
so navigation is fine — but pressing Enter on an entry there falls through our
`{ url = "*" }` fallback to `xdg-open` instead of reaching the preset's
`trash-restore` / `trash-empty` openers. Same story for VFS downloads.

### 1.4 git.yazi was only ever half-installed

`init.lua` called `require("git"):setup()`, which renders the status signs — but
the plugin is two halves, and the other half is a pair of `prepend_fetchers`
entries in `yazi.toml` that actually compute the statuses. Those were never
added, so the signs had been blank since the plugin went in on 2026-08-07. With
the fetchers registered, `Run fetcher 'git' with 12 target(s)` now shows up in
the task manager. (`group` is the current key name; it was `id` until v26.5.6,
which is why the author's own dotfiles still show the old spelling.)

### 1.5 Plugins pinned behind the binary — the "N left" that never clears

Found after the fetchers were wired up: the status bar kept a permanent `4 left`
and every quit raised *"There are unfinished tasks, quit anyway?"* listing
`Run fetcher 'git' with N target(s)`. The task manager showed them as **Failed**,
and the log said:

```
error converting Lua boolean to function
```

Not a fetcher problem — a version skew. `ya pkg` pins each package to a rev, and
the plugins installed on 2026-08-10 were still at `b9598e6`, from before yazi
v26.8.15 reworked the preloader/spotter/fetcher Lua API (#4235). The old
`fetch` returns `true`/`false`; the new API wants something else, hence
upstream's `6f26ae0`, "feat: simplify with new fetcher API" — where `fetch` is
`--- @since 26.8.15` and returns `require("noop"):fetch(job)`.

`ya pkg upgrade` moved every `yazi-rs/plugins:*` package to `6f26ae0` and the
failures, the `N left` counter and the quit prompt all went away, in a repo and
outside one.

The trap worth remembering: **`bin/update-all` upgrades the yazi binary
(`[yazi]=sxyazi/yazi`) but never runs `ya pkg upgrade`.** Until that is wired in,
every yazi release re-opens this exact bug, and the symptom (a stuck task
counter) points nowhere near the cause.

### 1.6 The ragged cursor row — empty `indicator.padding`

Reported as "why is the selected item's text indented?". It is the opposite:
the hovered row sits one column **left** of every other row.

Bisected rather than guessed — rendered yazi into a screen grid in a pty and
compared the column each filename starts at, section by section through the
flavor. Stock yazi is aligned; our flavor was not; the offending section was
`[indicator]`, and within it the single key `padding`. With the powerline caps
present the offset is 0, with `{ open = "", close = "" }` it is −1: yazi only
reserves the cap column on the cursor row when the strings are non-empty.

The strings were empty because U+E0B6 / U+E0B4 are private-use-area glyphs that
do not survive being copied between files. The *old* `yazi-theme.toml.tpl` had
already lost the same pair from `separator_open`/`separator_close`, so this
arrived pre-broken from the dotfiles-linux port and only became visible when the
key was carried onto the new schema, where it drives layout.

Fixed by writing them as TOML `\u` escapes — `padding = { open = "",
close = "" }` — which are plain ASCII in the template and cannot be lost
again. Verified: every row now starts at the same column.

Still deliberately empty, because they are longstanding style choices rather
than bugs: `tabs.sep_inner`/`sep_outer`, `status.sep_left`/`sep_right` (flat
segments instead of powerline caps), `cmp.icon_*` and `notify.icon_*`. Give them
`\u` escapes too if the powerline look is ever wanted.

### 1.7 Icons that render as letters — a font collision, not a missing glyph

Turning icons on surfaced a second-order problem: `~/Pictures` drew a literal
**j**, and a few other icons were wrong rather than absent.

Not a missing glyph. Maple Mono is the unpatched build, so icons come from
Symbols Nerd Font Mono via the `monospace` accept-list in
`50-qshell.conf` — and that mechanism only decides correctly when exactly one
font claims a codepoint. Fedora's `49-sansserif.conf` appends `sans-serif` to
any pattern carrying no generic name, `sans-serif` here resolves to Adwaita Sans
(Inter), and Inter keeps stylistic alternates in the private-use area. Where
both fonts cover a codepoint, the fallback can answer with Inter's letterform.

Measured against all 282 icon codepoints in yazi's preset set: exactly **8**
are also covered by Adwaita Sans — U+E21C, E244, E271, E28B, E28C, E2A6, EE72,
EEB6. (`fc-list ':charset=…'` is the tool for this; `fc-match` always returns a
best-effort family and will happily lie about coverage.)

Fixed in `templates/kitty.conf.tmpl`, since `symbol_map` bypasses fontconfig
for a range:

```
symbol_map U+E200-U+E2A9,U+ED00-U+EDFF,U+EE0C-U+F2FF Symbols Nerd Font Mono
```

The gap at U+EE00-U+EE0B is deliberate — Maple Mono ships its own glyphs there
— and the powerline block U+E0B0-U+E0B7 is left alone because Maple draws the
indicator caps that §1.6 depends on. Verified by loading the rendered config
through `kitty +runpy`: the three collision codepoints resolve to the symbols
font, while E0B6 and EE05 still fall through to fontconfig.

Note `U+F498` (the Downloads folder) is **not** a bug — it is
`nf-oct-desktop_download`, the glyph yazi's preset picks for that name. Override
it with `[icon] prepend_dirs` if a different one is wanted. foot has the same
exposure and is deliberately not changed; yazi only runs in kitty.

### 1.8 Three smaller keymap faults

- **`T` is bound twice** — `toggle-pane min-preview` (line 50) and the transcode
  helper (line 102). First match wins, so transcode is unreachable.
- **`t` shadows the new tab chords.** The preset moved tab creation to `t` ⇒ `t`
  in v26.5.6 and added `t` ⇒ `r` to rename a tab. Our single-key `t` = smart-tab
  matches first, so tab renaming can never fire. Upstream's own smart-tab tip now
  binds `[ "t", "t" ]` for this reason.
- **`shell … --confirm` is not a real option.** `ShellForm` in
  `yazi-parser/src/mgr/shell.rs` accepts only `block`, `orphan`, `interactive`,
  `cursor`, `cwd`. Ours is ignored.

## 2. What we're not using yet

Grouped by the release that added it, filtered to things that plausibly matter here.

**v25.12.29** — virtual filesystem + remote file management (`vfs.toml`, built-in
`sftp` scheme); shell formatting; per-task progress in the task manager;
`bulk_rename`; `casefy` in inputs; preview image zoom; `[app] overall`
background; `.deb` support; `copy dirpath`.

**v26.1.22** — the built-in archive previewer grew a **tree view** and learned
compressed tarballs (`.tar.gz`, `.tar.bz2`, …); file list refreshes when the
terminal regains focus.

**v26.5.6** — **custom tab names** (`t` ⇒ `r`); `app:theme` hot reload;
`sort_fallback`; `marker_symbol`; a `hovered` icon condition; multi-file spotter;
mouse pane resize; `ya exec` / `ya.exec()`; `ps.sub()` usable directly in
`init.lua`; custom plugin styles (`th.*`); Lua 5.5; an inline `lua` action.

**v26.8.15** — **trash bin** (`g` ⇒ `t`, with its own spotter/previewer and
restore/empty openers); **bulk create** (`A`); **help menu is now a command
palette** (filter always on, Enter runs the action — the `[help]` theme keys
changed with it); **input history** (`k`/`j`/`<C-p>`/`<C-n>` recall); **automatic
dark/light switching**; `%y`/`%Y` yanked-file and `%t`/`%T` cross-tab shell
params; H/M/L viewport motions; native drag-and-drop (already ours, via kitty);
context-aware input icons; file icons in the trash/delete/overwrite dialogs;
configurable `which` border.

Two structural ones worth calling out:

- **Flavors.** `ya env` reports `Dark/light flavor: "" / ""` — we use none. The
  flavor mechanism is now the recommended path over a hand-written `theme.toml`
  (it merges under the user's own file, ships a matching `tmtheme.xml` for code
  highlighting, and is what drives auto dark/light). Our theme is generated, so
  the natural move is to have `theme-apply` render a *flavor* rather than a bare
  theme — that gets us the syntax-highlighting palette for free.
- **VFS/SFTP.** `sftp://nuc` and `sftp://mini` would be genuinely useful given
  the fleet, and it is built in — a `vfs.toml` with two stanzas plus `g` ⇒ `n` /
  `g` ⇒ `m` bindings. Auth is via `$SSH_AUTH_SOCK` by default, `key_file` otherwise.

## 3. Plan

Ordered so that the correctness work lands before the cosmetics, and nothing in
a later phase depends on a plugin that hasn't been approved.

**Status 2026-08-18: phases 1, 3 and 4 are done** (user approved all four gates).
Phase 2 is not — every item in it either adds a config file or changes a
keymap surface that wasn't part of the approved set, so it is still a proposal.
Items below are marked `[x]` where they have landed and been verified.

### Phase 1 — repair (no new dependencies, no new keys) — **done**

1. [x] Migrate every `$@` / `$1` / `$0` to `%s` / `%s1` / `%h` across `yazi.toml` and
   `keymap.toml`. Use `%h` where the action is really about the hovered file
   (`transcode`, `add-sub`, `reveal`), `%s` where it is about the selection
   (`edit`, `play`, the clipboard yank).
2. [x] Rewrite `templates/yazi-theme.toml.tpl` onto the 26.8.15 schema; add the
   sections we never emitted (`[app]`, `[mode]`, `[tabs]`, `[indicator]`,
   `[cmp]`, `[spot]`, `[git]`), and drop `help.footer`.
3. [x] Add a yazi poke to `bin/theme-apply` so a theme switch lands in a running yazi
   like it already does for kitty/btop/helix: assign a per-window `--client-id`
   at launch, register it under `~/.local/state/qshell/`, and have `theme-apply`
   `ya emit-to <id> app:theme` each live one (§1.2 for why the broadcast form
   does not work).
4. [x] Convert `[open] rules` to `prepend_rules` so the preset's trash, VFS, folder
   and empty-file rules come back. Our extension-keyed video/audio rules and the
   PDF/Chromium picks stay as prepends; drop our `{ url = "*" }` fallback, which
   only exists to re-create what the preset already provides.
5. [x] Fix the keymap faults: move smart-tab to `t` ⇒ `t`, give transcode its own key
   (`T` stays toggle-pane), and drop the bogus `--confirm`.
6. [x] Decide `e`/extract: the built-in `extract` opener (`ya pub extract --list %s`)
   now handles nested and password-protected archives and feeds the task manager
   with progress. Proposal is to keep `ouch` only as an explicit "Open with"
   entry and let Enter use the built-in.

### Phase 2 — adopt what is already in the box (no installs) — **proposed, not done**

7. `vfs.toml` for `nuc` and `mini`, with `g` ⇒ `n` / `g` ⇒ `m` bindings.
8. `sort_fallback`, `marker_symbol`, `scrolloff` tuning, and the `hovered` icon
   condition in the theme.
9. Wire `%y` (yanked) and `%t`/`%T` (cross-tab) into a couple of genuinely useful
   bindings — e.g. "copy the yanked set somewhere else", "diff this tab's
   selection against the next tab's".
10. Custom tab names (`t` ⇒ `r`) — and then reconsider the hand-rolled tab strip
    in `init.lua`, which predates it and duplicates `[tabs]` theming badly.
11. Bulk create (`A`) and the command-palette help are free once the keymap is
    clean; the palette is worth a `desc` pass over our own bindings, since it is
    now a searchable surface rather than a static cheatsheet.

### Phase 3 — beautiful — **done**

12. [x] Render a **flavor** from `theme-apply` instead of a bare theme: `flavor.toml`
    plus a generated `tmtheme.xml`, so code previews are themed too, and set
    `[flavor] dark`/`light` for automatic switching.
13. [x] `[app] overall` background, `[indicator] padding` for the rounded indicator,
    `which` border, and a `[git]` style block driven from our palette tokens.
14. [x] Revisit `Status.redraw = {}` (our blanked status bar). The sixel/foot bug it
    works around was a *foot* problem; yazi now runs in kitty, where the KGP
    protocol has no such row semantics. Worth re-testing whether we can have a
    real status bar back — it is where permissions, symlink targets and task
    progress live.

### Phase 4 — plugins — **done** (all nine approved and installed)

All nine in §4's first two groups plus bunny were approved and are installed;
`ya pkg list` and the help palette both show them. Bindings are documented in
`keymap.toml`. ImageMagick is the one missing dependency — see §6.

## 5. Notes for anyone testing this headlessly

Two things will mislead you if you drive yazi in a bare pty rather than a real
terminal, both hit while verifying the above:

- **The user theme does not load.** `THEME` is initialised from the *preset*
  only (`yazi-config/src/lib.rs`); `theme.toml` is merged by `build_flavor`,
  which runs from the `app:theme` action, which the `Report` actor fires when
  the terminal answers **DA1**. Nothing answers DA1 in a bare pty, so yazi sits
  on the preset theme forever and every colour assertion comes out wrong. Answer
  `\e[?62;...c` (and OSC 11 for the background) from the driver and the real
  theme appears.
- **`sh -c` gets no positional arguments**, which is the whole reason §1.1 is
  true; a probe opener that logs `$@` next to `%s` shows it in one line.

Icons were **off** for most of this work and are now **on** (user ask, same
day). `theme.toml` had carried upstream's "hide all icons" recipe — five empty
`[icon]` arrays that *replace* the built-in nvim-web-devicons set — inherited
from the pre-2026 dotfiles-linux theme; enabling them was simply deleting the
block. Two preconditions were checked first: `fc-match ':charset=e5ff'` and
friends resolve to Symbols Nerd Font behind Maple Mono, and kitty's
icon-shrink bug (FAQ) needs the file list to carry a foreground colour, which
the flavor's `[filetype]` fallbacks supply. Their colours are devicons' own and
do not track the palette. Note this was never the cause of §1.6 — the cursor-row
offset reproduced identically with icons on, off, and off-with-a-placeholder.

## 6. Open questions

- Flavor vs theme: generating a flavor is more work in `theme-apply` (it wants a
  `tmtheme.xml` too) but is the only route to themed code previews and auto
  dark/light. Worth it?
- Status bar: re-enable now that yazi runs in kitty, or keep the minimal look?
- `restore.yazi` vs the built-in trash bin — keep both or drop the plugin?
- `ouch` vs built-in extraction as the Enter action on archives.
