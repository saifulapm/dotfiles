# UI audit — 2026-08-06

Full-surface audit for the polish phase, at tree 690fa7a (post perf S1-S4).
Every surface was screenshotted live (bar, 14 widget panels, launcher, menu
root + 7 submenus, theme switcher, wallpaper picker, emojis, clipboard,
reminder flow, volume/brightness OSD, notification toasts normal+critical,
polkit dialog, lock preview) and inspected at pixel zoom; the code catalog
below was produced by a line-by-line sweep of `shell/Modules/**` and
`shell/components/`. Screenshots live in the job scratch dir, referenced by
description only.

Verdict up front: the surfaces are in good shape — the bar matches its
omarchy spec, panel content reads well, scrim dimming is uniform across all
seven fullscreen overlays (measured 48→40 mean RGB in the same region), and
nothing is visually broken. The debt is almost entirely *structural*: six
omarchy-ported panels each carry a private copy of the same inline component
library, and the copies have started to drift (four letter-spacing values,
two header typefaces, three micro-durations, four card widths). The fixes
are correspondingly mechanical: extract once, converge the drift onto the
majority value.

Builtin token values (Commons/defaults.js): space.unit 4 → `space(n)` = 4n px,
radius 8, border-width 1, font.size 12 → `fontPx(m)` = 12m, motion.duration
150 → `time(n)` = 150n ms.

## C. Visual findings (screenshot pass)

- **C1 — header typeface drift (converge, visible change)**: Power, Monitor
  and Ai panels set section headers in fontUi; Audio, Network, Bluetooth,
  Tailscale, Media, Rclone use fontMono. One family draws the whole shell,
  so the difference is subtle today, but the mono recipe is the majority and
  the omarchy source style — converge all headers on the shared
  SectionHeader. Same for hero-meta caption lines (mono in Audio/Bluetooth/
  Network, fontUi in Power/Monitor/Ai). letterSpacing converges 1/1.2/1.5 →
  1.2 (display titles at ls 2 stay).
- **C2 — Monitor BRIGHTNESS row (compaction)**: with a single backlight the
  per-row label line renders as an almost-empty line holding only the
  right-aligned "58%" (MonitorPanel.qml:432; the output name at :450 hides
  itself when rows == 1). Audio's OUTPUT header carries its value on the
  header line. Fix: give Monitor's BRIGHTNESS header the shared
  SectionHeader value slot when there is one row, and hide the empty line —
  one line tighter, converges with Audio. Risk: low; multi-output keeps the
  per-row labels.
- **C3 — everything else checks out**: bar glyph centering/baselines clean at
  4× zoom; panel row heights consistent; scrim uniform (measured); calendar,
  weather, battery, AI, network hero grids all aligned; notification
  critical/normal variants correct; polkit + lock preview correct; menu
  root scrolls past Setup by design (matches upstream, no scroll cue —
  status quo wins).
- **Pre-existing, UI-adjacent**: NetworkPanel binding loop fires with wifi
  action-status text (report §8 side finding) — fix if convenient during
  the panel work.
