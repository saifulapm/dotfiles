# Dictation, after voxtype 1.x and the community plugins — 2026-09-04

User ask: fix voxtype, look at the Quickshell integration the latest release
ships, clone every voxtype plugin from the omarchy community marketplace, read
them, and build a dictation panel of our own.

**Nothing was installed from the marketplace.** All eleven repos target
`omarchy-shell` on Hyprland — `omarchy plugin add`,
`~/.config/omarchy/plugins/`, `hyprctl activewindow`, omarchy's plugin
registry. Same rule as the 2026-08-21 marketplace port and the notification
one earlier today: the repos were read for behaviour and for the decisions
worth keeping, and everything here is written against our own tree. Clones are
at `~/ref/voxtype-plugins/` for reading, upstream voxtype at `~/ref/voxtype`.

## The bug that mattered

**The microphone is muted at rest, so every dictation was recording digital
silence.**

The default source here is the Asahi `j493` mic filter-chain, and
`wpctl get-volume @DEFAULT_AUDIO_SOURCE@` reports `Volume: 0.70 [MUTED]` —
the resting state the bar's Mic widget and `XF86AudioMicMute` both maintain,
and the right one for a laptop. voxtype neither knows nor cares: it opens the
capture stream and PipeWire hands it a muted source.

Measured through `voxtype-audio-bridge`, which is what made it provable rather
than suspected:

| default source | frames in a recording | non-zero | peak |
|---|---|---|---|
| muted | 138 | **0** | 0.000 |
| unmuted | 147 | 144 | 0.203 |

And with `vad.enabled` false (voxtype's default, and ours at the time), silence
is not even an empty transcript — it is whatever whisper hallucinates onto it. A test
recording of real speech played into the room came back `"Thank you."`, which
is the canonical whisper-on-silence output.

`bin/voxtype-mic-gate` is the fix, and it opens the mic for the length of ONE
recording rather than permanently: the mute IS the privacy posture, and a
microphone that opens on the dictation key and shuts when recording ends is a
stronger posture than a live one, not a weaker one. The close is owned by the
open — a forked waiter on the state file — so it also covers `record cancel`,
the 60 s `max_duration` ceiling and a daemon that dies mid-utterance;
`bin/voxtype-idle-stop` sweeps as a net every 2 min in case the waiter is
killed.

`output.pre_recording_command` is where this belongs, and voxtype runs it on
every recording path — but **`voxtype config set` rejects that key** (it parses
from the file, it is absent from the settable schema; verified on 1.0.1), and
`config.toml` is deliberately not chezmoi-managed. `bin/voxtype-toggle` is the
single entry point every dictation here goes through — the keybind and the bar
widget both spawn it — so the gate hangs off that instead.

## The version pin moved: 0.7.5 → 1.0.1

The old note in `run_after_01-voxtype.sh` said 0.7.5 was "the newest release
with linux assets at all". True of `v1.0.0-rc1` (macos-universal only), wrong
since **v1.0.0** (2026-08-29). 1.0.1 ships every arch we use.

The pin is now a **floor the shell depends on**, not a preference: the panel is
built on `config schema --json`, `config get/set` and
`info accel|models|engines --json`, none of which exist before 1.0.0.

1.1.0 was left alone — in rc since 2026-09-01, and its headline features (OSD
style packages, OpenVINO NPU) are for a frontend and hardware we do not have.

Two behaviour changes in the install script:

- **The pin now wins.** It used to install only a MISSING binary so a hand
  `voxtype check-update` was never stomped. With QML built against a 1.x CLI,
  "whatever happens to be on disk" is not a version anything can rely on.
  Keeping a hand-upgrade means bumping `VERSION`.
- **A second binary**: `voxtype-audio-bridge`, the sidecar the OSD waveform
  reads. A failed fetch costs the waveform and nothing else, so it warns rather
  than failing the install.

## Upstream's own Quickshell integration, and why we did not take it

voxtype 1.x ships two things, neither drop-in:

- **`quickshell/`** — a real OSD frontend (`voxtype-osd-quickshell`,
  `[osd] frontend = "quickshell"`). It runs as a **second `qs -p` process**
  with its own QML tree, its own generated theme file and its own idea of our
  palette. One quickshell on this desktop is the whole point of the shell, and
  a second one told our colours through a JSON file is a worse version of
  reading `theme` directly. `[osd] enabled` stays **false**; our OSD reads the
  same audio bridge theirs does.
- **`omarchy-plugin/`** — a settings panel (`io.voxtype.settings`) that renders
  all 95 keys of `config schema --json` inside `omarchy-shell`. We have no
  plugin registry, and a panel listing every setting is a TUI with worse
  ergonomics. `voxtype configure` already is the TUI; it is one chip away in
  the panel header.

What we did take from them is the **rule**, which is worth copying verbatim:
every reading is measured, and one that could not be taken is left out rather
than guessed — so a missing item means "not known" and never "zero".

## What landed

### The dictation log — `bin/voxtype-capture`

voxtype types a transcript into the focused window and then forgets it. There
is no history and no way to recover a paragraph that landed in the wrong
window because focus moved while whisper was thinking.
`output.post_process.command` (the one hook `config set` accepts) now points at
a passthrough filter that types the transcript back out unchanged and keeps a
copy.

Two stores on purpose: `dictation.jsonl` is pruned to 500 unpinned
transcripts, `dictation-days.json` is a ~60-byte-a-day rollup that is not — so
stats do not vanish with the 501st dictation. Both `0600` under
`$XDG_STATE_HOME/qshell`.

It is load-bearing on the typing path, so the passthrough is the FIRST thing it
does and every failure below it is caught. **Verified**: an unwritable store
still types the transcript and exits 0.

### The panel — `DictationPanel.qml`

State, the two knobs that change day to day, and the two questions voxtype
cannot answer because it keeps no record. Opened from the bar's dictation
indicator: **left-click opens the panel** (it used to toggle recording),
right-click records, middle-click opens the TUI. Nothing lost a binding — at
the time the keybinds were `Mod+Ctrl+X` and `F9`, and they are Alt-Alt now
(see the second round below).

Panel-gated throughout: the facts snapshot runs on open and after actions,
never on a cadence, and the three file watches only exist while it is open. A
shell whose dictation panel is never opened pays for none of it.

### The OSD — `Modules/Osd/DictationOsd.qml`

Top-centre card with a mirrored 64-bar waveform off the audio bridge, and a
sweep while whisper works (the mic is already shut by then, so freezing on the
last syllable would read as "still listening"). The bridge is gated on
`recording`, so it is one process only while one is in flight — **verified**
spawning at record and exiting at stop.

Not the OSD pill next door: that is a show-and-timeout surface, dictation is a
state you are IN.

## Bugs found and fixed along the way

1. **`install` fails ETXTBSY over a running daemon.** The upgrade path wrote
   the binary directly; a machine mid-session (the daemon lingers after
   any dictation) got "install failed (download or checksum)" for what was
   neither. Now installs beside and renames over — atomic, and the running
   process keeps its old inode. Verified by upgrading 0.7.5 → 1.0.1 with the
   daemon live.
2. **A rename leaves the daemon on the old build.** The script now
   `try-restart`s it, skipped mid-recording. Verified: main PID changes,
   `daemon_version_differs` goes false.
3. **`eventPoint.event` is undefined on this Qt.** One `TapHandler` taking both
   buttons and branching on `eventPoint.event.button` throws, and **a throwing
   `onTapped` silently does nothing** — the history rows looked inert under
   both buttons while their hover highlight worked perfectly. One handler per
   button, which is what `BarButton` already does.
4. **`info accel` cries `cpu-fallback` on a machine with no GPU.** Every
   aarch64 install lands there (upstream ships CPU-only arm64 binaries and says
   so). `gpuPresent: false` from `info variants --json` demotes it to a plain
   "CPU"; `null` leaves the warning intact, because "could not tell" must not
   silence a real fallback.
5. **The facts line said `unit inactive` while the hero said `Listening`.** The
   first dictation of a session STARTS the daemon; the snapshot now refreshes
   on state changes, panel-gated.
6. **"1 dictations across 1 day".** Moved into `Model.summaryText` with a test.

## Known upstream limitation, not worked around

`voxtype config unset output.post_process.command` is **broken on 1.0.1**: it
removes `command`, leaves an empty `[output.post_process]` table, fails its own
validate-after-write and rolls back. The way to stop logging is
`voxtype-capture pause`, not an unset.

`daemon_version_differs` cannot see a pre-1.0 daemon — 0.7.5 writes no
`$XDG_RUNTIME_DIR/voxtype/version` file, so a stale one reads as current. It
works between 1.x versions. The panel line for it is therefore **written but
not observed firing**; everything else here was driven on screen.

## Second round, same day: Alt-Alt, VAD, and the cost question

### Alt-Alt replaces both keybinds

`Mod+Ctrl+X` and `F9` are **gone**. Dictation starts and stops on a double-tap
of a bare Alt, which niri cannot express — a bind is a key chord plus
`repeat` / `cooldown-ms` / `allow-when-locked` / `allow-inhibiting` /
`hotkey-overlay-title` and nothing else, with no tap binds and no release
binds.

So it went where Shift-Shift already lives: `packages/src/qshell-dshift.c`, the
evdev watcher behind the notes capture. It now carries a table of watched
modifiers rather than a hardcoded Shift, and the modifiers reset each other, so
Shift-then-Alt is a chord and not half of two pairs. Extending it rather than
shipping a second watcher is the point — the poll loop and device rescan are
already there, and a second always-on service would double the wakeups on every
keystroke to read the same events twice. **Resident cost after: 1232 kB,
against 1280 kB before.**

The name `qshell-dshift` is now historical. Renaming the binary means renaming
the unit, which leaves an orphaned enabled service on every machine that
already has the old one — not worth it for a filename.

**One consequence that needed a new guard.** An evdev watcher does not care
what the compositor is showing, so unlike a niri bind it fires *under the
session lock*. Without a guard, two taps at a locked screen would open the
microphone and transcribe into whatever got focus at unlock.
`bin/voxtype-toggle` now refuses to START while locked — it will still stop a
dictation the lock landed on top of, since stopping is safe in every case. Same
check `bin/notes-quick-capture` has always carried.

Verified by driving uinput with `ydotool` (`wtype` uses the virtual-keyboard
protocol and is invisible to evdev, so it cannot test this at all):

| input | result |
|---|---|
| Alt Alt | starts, mic opens |
| Alt Alt again | stops, mic re-mutes |
| Alt+key chord ×2 | inert |
| single Alt tap | inert |
| two Alt taps 700 ms apart | inert |
| Shift then Alt | inert |
| Alt then Shift | inert |
| Shift Shift | still opens Notes |

### VAD is on

**What it is:** voice activity detection. It checks whether a finished
recording contains speech at all, and throws it away before whisper ever sees
it if not.

**Why it was worth it here, measured on a 10 s silent take:**

| | wall | daemon CPU | output |
|---|---|---|---|
| VAD off | 14.5 s | **16.8 s** | typed `"Thank you."` |
| VAD on | 10.2 s | **0.25 s** | nothing |

Whisper does not return an empty string for silence — it hallucinates one, and
voxtype types it. That is the same `"Thank you."` that turned up in the first
round's end-to-end test. So VAD is worth 67× the CPU and the whole class of
wrong paste, and it matters more now that Alt-Alt makes an accidental start a
one-hand slip.

The model is Silero, **868 KB** (`voxtype setup vad`), against small.en's
466 MB. `vad.backend` is left at `auto`, which picks Silero for whisper and the
model-free energy detector for the ONNX engines. Both directions verified: a
silent take is rejected, and real speech still transcribes — poor
speaker-to-mic audio at that, so the default threshold of 0.5 is not too
aggressive here. If a quiet voice ever gets dropped,
`voxtype config set vad.threshold 0.3` is the knob.

**The rejection is silent.** The daemon logs it at DEBUG, plays a Cancelled
sound only when `audio.feedback.enabled` is true (false here), and otherwise
returns to idle. A dropped dictation looks like one that produced nothing.

### VAD is not enough, and the reason is the microphone

VAD catches a *fully silent* recording. It does not catch this machine's
microphone in a normal room. Measured across ten silent takes:

| setting | takes that still reached whisper |
|---|---|
| `threshold = 0.5` (default) | 4 of 6 |
| `threshold = 0.7` | 4 of 4 — **worse** |
| `min_speech_duration_ms = 1000` | 4 of 5 |

Every one that got through produced a hallucination: `"Thank you."`,
`"Thanks for watching!"`, `"Go! Please!"`, `"Oh shoot, they took my foot."`

**Why no VAD knob fixes it.** Measured through `voxtype-audio-bridge`, a
"quiet" room here peaks at **0.256**, with 524 of 528 frames above the
bridge's own −40 dBFS speech threshold — *louder than a real-speech test that
peaked at 0.203*. VAD is not being fooled; the microphone genuinely hears that
much. No threshold separates signal from noise when the noise is the size of
the signal, which is also why raising the threshold measured worse.

So `vad.enabled = true` stays (it catches the genuinely silent case and saves
the 16.8 s of CPU there), `vad.threshold` stays at the default, and
`min_speech_duration_ms` is deliberately NOT set — it was tried at 1000 ms,
rejected 1 of 5, and would have cost every sub-second dictation.

**The real lever is the microphone**: the input is hot (source at 0.70 through
the Asahi j493 filter chain). A quieter room or a lower capture gain is what
moves this, and it would improve real transcription accuracy too — whisper is
currently decoding speech buried in that noise floor.

### The hallucination filter

`bin/voxtype-capture` drops a transcript matching upstream's own
`HALLUCINATION_PATTERNS` list before it is typed, and logs it to the history
marked `dropped` so nothing is destroyed — the panel shows it greyed with
"not typed". The list and its normalisation are copied verbatim from
voxtype's `src/transcribe/sliding_window.rs`; upstream already drops these, but
only on the streaming path, which push-to-talk does not use.

It needs `fallback_on_empty = false` in `config.toml`, because with the default
`true` a hook that prints nothing makes voxtype type the *original* text. That
key and `vad.min_speech_duration_ms` are both unsettable through
`voxtype config set`, so `run_after_01` writes them with a guarded `awk` that
keeps a backup and verifies by asking voxtype to parse the file back.

**It is a partial fix, honestly.** It catches the canonical phrases — which was
6 of the hallucinations seen — but not arbitrary ones like
`"Oh shoot, they took my foot."` The remaining protection is that the OSD card
is on screen the whole time you are recording, so an accidental trigger is
visible, and every transcript is in the history either way.

### What voxtype actually costs

| | RSS | CPU |
|---|---|---|
| at rest (nothing dictated for ~90 s) | **0** — daemon stopped | **0** |
| the always-on bits | `voxtype status --follow` 4.2 MB + `qshell-dshift` 1.2 MB | 0.06 s over a shell lifetime |
| daemon up, idle | 498 MB (486 MB of it the model) | 0.04 s / 30 s = **0.13 %** |
| transcribing 10 s of audio | **882 MB peak** | 16.8 s across ~3.7 of 8 cores, for ~4.5 s |

The peak is the number to know: whisper.cpp roughly doubles the resident model
while decoding, so a dictation briefly costs ~880 MB on a 7.3 GB laptop. It
falls back to ~500 MB immediately and to zero when the idle timer reaps the
daemon — which is exactly why the on-demand arrangement exists, and why the
answer to "does voxtype eat memory" is "only while you are dictating".

Everything added with the panel is noise by comparison: `voxtype-audio-bridge`
3.6 MB and **0.00 s of CPU** for a whole recording, `bin/voxtype-capture`
0.02 s per dictation, `bin/voxtype-facts` 0.12 s per panel open.

## Third round: the rest of the config, and meeting mode

### Settings turned on

| Key | Why |
|---|---|
| `whisper.initial_prompt` | Whisper conditions decoding on this text, so naming the vocabulary actually dictated here (Laravel, pnpm, PostgreSQL, niri, quickshell, chezmoi…) biases it toward the right spelling. This is the documented fix for the failure already recorded in the manifest — base.en hearing "restock PostgreSQL" as "restot Postger SQL". Free at runtime. |
| `audio.feedback.enabled` | Synthesised tones, nothing to download. The one that matters is **Cancelled**, which is what a VAD rejection plays — without it a rejected dictation is silent and indistinguishable from one that never recorded, which was the single most confusing thing about having VAD on. |
| `output.shift_enter_newlines` | Enter submits in Claude Code, Slack and most chat inputs, so a dictated multi-line message fired off at the first line break. |
| `meeting.enabled` | See below. |

These are written **once and never corrected**, unlike the post-process hook.
The test is the schema's `file_value`: `null` means the key is absent from
config.toml entirely, anything else means somebody chose it. `config get`
cannot answer this — it reports the resolved value, and an unset bool is
indistinguishable from an explicit `false`.

`whisper.eager_processing` was offered and declined; it changes chunk
boundaries, so it wants a real accuracy test rather than a flag flip.

### Meeting mode

Long-form continuous recording: chunked, transcribed per chunk, stitched into
a timestamped transcript under `~/.local/share/voxtype/meetings/` (SQLite index
plus a folder per meeting). `loopback_device` defaults to `auto`, which
captures the far side of a call as well as the mic. `voxtype meeting
list|show|export|summarize|label|delete` do the rest.

Wired three ways: **Mod+Alt+M** (a chord, not a tap — it is a once-a-call
deliberate action, and `Mod+Ctrl+M` is cliamp), a **MEETING row in the panel**
with Start/Stop, Pause/Resume and a Transcripts button, and the **bar
indicator**, which now lights for a meeting as well as a dictation. That last
one is the point: a meeting records for an hour with nothing else on screen to
say so, and an indicator that stayed dark through it would be the shell keeping
a secret about an open microphone.

**Meeting mode is a SECOND state machine, and that broke two things.** The
daemon leaves the dictation `state` file on `idle` for the entire length of a
meeting and tracks it in `meeting_state` instead (a two-line `status\nid` file).
Verified 2026-09-04. So before this landed:

- `bin/voxtype-idle-stop` would have read "idle for ten minutes" partway
  through an hour-long meeting and **stopped the daemon underneath it**, losing
  the recording.
- `bin/voxtype-mic-gate` would have shut the microphone **five seconds into**
  the meeting.

Both now watch `meeting_state` too, and the gate's 300 s ceiling is pushed
forward while a meeting is live rather than applied to it.

### Two traps found wiring the guard

1. **`voxtype meeting status` is not a cross-check.** It reads `meeting_state`
   itself and will repeat whatever the file says, including a stuck claim.
   `meeting show <id>` goes to the meetings database and answers "Meeting not
   found" for an id that is gone — that is the real check. (It exits 0 either
   way, so the output is what gets read.)
2. **`pipefail` + `grep -q` inverted the guard.** `voxtype meeting show … |
   grep -qi "not found"` — grep closes the pipe on its first match, voxtype
   dies of SIGPIPE, and the pipeline reports failure *even though the match
   succeeded*. The negation then read "this id is fine" for an id that was
   gone, and a stale claim kept the daemon alive forever. Captured into a
   variable and matched with `[[ ]]` instead. Same trap already recorded
   against the omarchy scripts.

The stuck state is reachable: deleting a meeting that is still recording leaves
the daemon logging `Meeting not found` on every stop attempt and the file frozen
at `recording`. A daemon restart clears it.

### The Quickshell OSD, asked again

Still no. `voxtype-osd-quickshell` runs as a **second `qs -p` process** with its
own QML tree and generated theme file. Ours is inside the existing shell, in the
real theme, reading the same `voxtype-audio-bridge` sidecar. The TUI's "OSD
binaries not installed" warning is that decision showing up, not a fault.

## The daemon's idle window: 10 min → 90 s

Asked whether the daemon should linger at all after a dictation, given a
typical gap of hours before the next one. It already did the right shape of
thing — `voxtype.service` is `disabled`, so nothing starts it at login, and
`voxtype-idle-stop.timer` reaps it — but the window was ten minutes, copied
from the podman database containers.

That copy did not survive measurement. A cold start on 1.0.1 with VAD:

| | measured |
|---|---|
| cold (daemon down → ready) | **0.165 / 0.196 / 0.164 s** |
| warm (already up) | 0.007 / 0.010 s |
| resident while up | 510 MB (493 MB of it the model) |

The 0.17 s lands *before* recording starts — the wrapper waits for the daemon's
state file, then sends the toggle — so the entire cost of having reaped the
daemon is a sixth of a second spent not having started speaking yet. Ten
minutes of ~510 MB was buying that. For the databases the trade makes sense (a
cold container is seconds); here it does not.

So: **window 600 s → 90 s, timer period 2 min → 45 s.** The period has to stay
below the window, or the timer rather than the window decides when RAM comes
back — a 2 min tick against a 90 s window would reap somewhere between 90 s and
3.5 min. Ticking more often is nearly free: with the daemon stopped, which is
now the common case, the check is one `stat()` on a path that does not exist.

Verified end to end: after a finished dictation the daemon was **reaped at
T+100 s**, inside the expected 90–145 s band, with the microphone restored and
no process left.

Ninety rather than thirty because a burst — dictate, read it, dictate again —
should stay warm, and 90 s covers reading a paragraph and going again.

## What was deliberately not done

- **Parakeet / the `-onnx` binary.** Markedly faster on CPU with real
  punctuation, but it is a different 42 MB binary and a ~600 MB model, and its
  aarch64 performance is unmeasured (the docs tune it for AVX2/AVX-512). A
  benchmark first, not a swap.
- **Meeting mode, engine picker, style packages.** 1.x features for setups
  that are not this one.

`vad.enabled` was on this list at the end of the first round, as "worth
having, but a separate download decision". It was measured and turned on in
the second round above — the model turned out to be 868 KB.
